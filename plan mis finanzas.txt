# Plan de Trabajo — Mis Finanzas PWA v2.0

## Documento técnico de mejoras para programador

**Proyecto:** Mis Finanzas — PWA de finanzas personales
**Estado actual:** Maqueta funcional con registro de ingresos/gastos, presupuestos básicos, reportes y exportación CSV.
**Objetivo:** Convertirla en una app de gestión financiera completa y profesional, al nivel de Wallet (BudgetBakers), Bluecoins o Monefy.
**Stack:** React 18 (JSX con Babel in-browser), Recharts, Lucide React, cargados desde ESM/CDN. Todo en un solo `index.html`. Datos en localStorage vía shim `window.storage`. PWA con Service Worker.

---

## Contexto técnico

- **Arquitectura:** Single-file app. Todo el código React está dentro de `<script type="text/babel">` en `index.html`. No hay build step.
- **Estado global:** Un único objeto `data` con `useState` en `<App>`, que contiene `transactions`, `categories`, `budgets`, `settings`. Se persiste entero en localStorage bajo la clave `finanzas_data_v1`.
- **Navegación:** Tabs en bottom nav: Inicio, Historial, Metas, Reportes, Ajustes. Modales y bottom sheets para formularios.
- **Diseño:** Sistema de temas (dark/light) con objeto `THEMES`. Tipografía: Fraunces (serif, títulos) + Inter (sans, cuerpo). Paleta dorada/cálida.
- **PWA:** Service Worker con cache-first para archivos propios, network-first para CDN. Manifest con iconos 192/512/maskable.

### 1.1 Sistema de cuentas múltiples

**Qué hace:** Permite crear y gestionar múltiples cuentas financieras (efectivo, cuenta bancaria, tarjeta de crédito, billeteras digitales como Nequi/Daviplata, cuenta de ahorros). Cada transacción se asocia a una cuenta. Cada cuenta tiene su propio saldo.

**Cambios en el modelo de datos:**

```javascript
// Agregar al objeto data:

  {
    id: string,
    name: string,              // 'Bancolombia Ahorros', 'Efectivo', 'Nequi'
    type: 'cash' | 'bank' | 'credit_card' | 'savings' | 'digital_wallet' | 'investment',
    icon: string,              // Ícono Lucide
    color: string,             // Hex
    initialBalance: number,    // Saldo inicial al crear la cuenta
    currency: string,          // Moneda de esta cuenta
    includeInTotal: boolean,   // Si se incluye en el balance global
    archived: boolean,         // Para ocultar sin borrar
    order: number              // Orden de visualización
  }
],

// Modificar cada transacción:
transactions: [
  {
    ...camposActuales,
    accountId: string,         // REEMPLAZA el campo 'method'
    // El campo 'method' se elimina
  }
]

// Agregar nuevo tipo de transacción para transferencias entre cuentas:
// type: 'transfer'
// Campos adicionales para transferencias:
// toAccountId: string
```

**Cuentas por defecto (precargar al primer uso):**
- Efectivo (cash, ícono: Banknote, color: #8FBFA0)
- Cuenta bancaria (bank, ícono: CreditCard, color: #8FA7D9)
- Tarjeta de crédito (credit_card, ícono: CreditCard, color: #D98C7A)

**UI necesaria:**

1. **Pantalla de cuentas** — Accesible desde Inicio, muestra lista de cuentas con saldo individual. Cada cuenta es un card con ícono, nombre, saldo. Botón "+" para agregar cuenta.
2. **Selector de cuenta en TransactionSheet** — Reemplazar los botones de "Método" (Efectivo/Tarjeta/Transferencia) por un selector de cuenta. Si el tipo es 'transfer', mostrar cuenta origen y cuenta destino.
3. **Formulario de nueva cuenta** — Modal con campos: nombre, tipo (selector), ícono, color, saldo inicial, moneda, incluir en total (toggle).
4. **Saldo de cada cuenta** — Se calcula como: `saldoInicial + ingresos - gastos + transferenciasRecibidas - transferenciasEnviadas`

**Lógica de cálculo de saldos:**

```javascript
function getAccountBalance(accountId, transactions, accounts) {
  const account = accounts.find(a => a.id === accountId);
  let balance = account.initialBalance || 0;
  
  transactions.forEach(tx => {
    if (tx.accountId === accountId) {
      if (tx.type === 'income') balance += tx.amount;
      if (tx.type === 'expense') balance -= tx.amount;
      if (tx.type === 'transfer') balance -= tx.amount; // origen
    }
    if (tx.type === 'transfer' && tx.toAccountId === accountId) {
      balance += tx.amount; // destino
    }
  });
  
  return balance;
}
```

**Migración de datos existentes:**
Al cargar datos v1, si no existe `accounts`, crear la cuenta "Efectivo" por defecto y asignar `accountId: 'efectivo'` a todas las transacciones existentes. Mapear el campo `method` anterior: 'Efectivo' → cuenta efectivo, 'Tarjeta' → crear cuenta tarjeta, 'Transferencia' → cuenta banco.

**Tarjetas de crédito:**
Las tarjetas de crédito son especiales: el saldo es negativo (deuda). Un gasto con tarjeta AUMENTA la deuda. Un pago a la tarjeta es una transferencia desde otra cuenta.

**Lógica de generación automática:**
Al abrir la app (en el `useEffect` de carga inicial), después de cargar datos:

```javascript
function processRecurringTransactions(data) {
  const today = todayISO();
  let newTransactions = [...data.transactions];
  let updatedRecurring = data.recurringTransactions.map(rec => {
    if (!rec.active) return rec;
    if (rec.endDate && rec.endDate < today) return { ...rec, active: false };
    
    let nextDate = rec.nextDueDate || rec.startDate;
    const generated = [];
    
    while (nextDate <= today) {
      // Crear transacción
      generated.push({
        id: uid(),
        createdAt: Date.now(),
        type: rec.type,
        amount: rec.amount,
        category: rec.category,
        accountId: rec.accountId,
        date: nextDate,
        note: rec.note ? `${rec.note} (recurrente)` : '(recurrente)',
        recurringId: rec.id  // Para identificar origen
      });
      nextDate = calculateNextDate(nextDate, rec.frequency, rec.dayOfMonth);
    }
    
    newTransactions = [...newTransactions, ...generated];
    return { ...rec, nextDueDate: nextDate, lastGeneratedDate: today };
  });
  
  return {
    ...data,
    transactions: newTransactions,
    recurringTransactions: updatedRecurring
  };
}
```

### 3.1 Respaldo y restauración completa

**Qué hace:** Permite exportar todos los datos de la app como archivo JSON (respaldo completo) e importarlos de vuelta. Opcionalmente, sincronizar con Google Drive.

**Implementación — Nivel 1 (JSON local):**

```javascript
// Exportar
function exportFullBackup(data) {
  const backup = {
    version: 2,
    exportedAt: new Date().toISOString(),
    app: 'MisFinanzas',
    data: data  // Todo el objeto data completo
  };
  const blob = new Blob([JSON.stringify(backup, null, 2)], { type: 'application/json' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = `mis-finanzas-backup-${todayISO()}.json`;
  document.body.appendChild(a);
  a.click();
  document.body.removeChild(a);
  URL.revokeObjectURL(url);
}

// Importar
function importFullBackup(file) {
  return new Promise((resolve, reject) => {
    const reader = new FileReader();
    reader.onload = (e) => {
      try {
        const backup = JSON.parse(e.target.result);
        if (backup.app !== 'MisFinanzas') throw new Error('Archivo no válido');
        // Validar estructura mínima
        if (!backup.data || !backup.data.transactions) throw new Error('Datos incompletos');
        resolve(backup.data);
      } catch (err) {
        reject(err);
      }
    };
    reader.readAsText(file);
  });
}
```

### 3.2 Mejorar el exportar CSV

**Mejoras al CSV actual:**

1. Agregar columna de cuenta (nombre de la cuenta)
2. Agregar columna de tags
3. Agregar columna de saldo acumulado
4. Opción de exportar solo el período seleccionado (no todo)
5. Separar el monto en dos columnas: Ingreso y Gasto (facilita importar en Excel)
6. Agregar BOM UTF-8 para que Excel abra bien los acentos

```javascript
function exportCSV(transactions, categories, accounts, settings, dateRange) {
  const BOM = '\uFEFF';  // BOM para UTF-8 en Excel
  const header = 'Fecha,Tipo,Categoría,Cuenta,Monto,Ingreso,Gasto,Nota,Etiquetas\n';
  
  let filtered = transactions;
  if (dateRange) {
    filtered = filtered.filter(tx => tx.date >= dateRange.from && tx.date <= dateRange.to);
  }
  
  const rows = filtered
    .sort((a,b) => a.date.localeCompare(b.date))
    .map(tx => {
      const cat = categories.find(c => c.id === tx.category);
      const acc = accounts.find(a => a.id === tx.accountId);
      const ingreso = tx.type === 'income' ? tx.amount : '';
      const gasto = tx.type === 'expense' ? tx.amount : '';
      const tags = (tx.tags || []).join('; ');
      const nota = (tx.note || '').replace(/,/g, ';');
      return `${tx.date},${tx.type === 'income' ? 'Ingreso' : 'Gasto'},${cat?.name || 'Otros'},${acc?.name || ''},${tx.amount},${ingreso},${gasto},${nota},${tags}`;
    }).join('\n');
  
  const blob = new Blob([BOM + header + rows], { type: 'text/csv;charset=utf-8;' });
  // ... descarga
}
```

### 4.4 Multi-moneda simultánea

**Qué hace:** Cada cuenta puede tener su propia moneda. Al mostrar totales globales, se convierten a la moneda principal del usuario.

**Implementación:**

```javascript
// Cada cuenta ya tiene campo 'currency'
// Agregar al settings:
settings: {
  ...existente,
  mainCurrency: 'COP',  // Moneda base para mostrar totales
  exchangeRates: {       // Tasas manuales (el usuario las actualiza)
    'USD': 4150,         // 1 USD = 4150 COP
    'EUR': 4500,
  },
  exchangeRatesUpdatedAt: string  // Fecha de última actualización
}

// Función de conversión
function convertToMainCurrency(amount, fromCurrency, settings) {
  if (fromCurrency === settings.mainCurrency) return amount;
  const rate = settings.exchangeRates[fromCurrency];
  if (!rate) return amount;
  
  // Si mainCurrency es COP y fromCurrency es USD: amount * rate
  // Si mainCurrency es USD y fromCurrency es COP: amount / rate
  // Simplificación: la tasa siempre se guarda como "1 [foreign] = X [main]"
  return amount * rate;
}
```

```javascript
function evaluateExpression(str) {
  // Solo permitir números y operadores básicos
  const sanitized = str.replace(/[^0-9+\-*/().]/g, '');
  try {
    const result = Function('"use strict"; return (' + sanitized + ')')();
    return Number.isFinite(result) ? result : null;
  } catch {
    return null;
  }
}
```

  // 1. Crear cuentas por defecto basadas en methods usados
  const methods = new Set(oldData.transactions.map(tx => tx.method).filter(Boolean));
  const accounts = [
    { id: 'efectivo', name: 'Efectivo', type: 'cash', icon: 'Banknote', color: '#8FBFA0', initialBalance: 0, currency: oldData.settings.currency, includeInTotal: true, archived: false, order: 0 },

  }
  if (methods.has('Transferencia')) {
    accounts.push({ id: 'banco', name: 'Cuenta bancaria', type: 'bank', icon: 'Wallet', color: '#8FA7D9', initialBalance: 0, currency: oldData.settings.currency, includeInTotal: true, archived: false, order: 2 });
  }
  
  // 2. Mapear method → accountId en transacciones
  const methodToAccount = { 'Efectivo': 'efectivo', 'Tarjeta': 'tarjeta', 'Transferencia': 'banco' };
  const transactions = oldData.transactions.map(tx => ({
    ...tx,
    accountId: methodToAccount[tx.method] || 'efectivo',
    tags: [],
    // Eliminar method
  }));
  transactions.forEach(tx => delete tx.method);
  
  // 3. Retornar estructura v2
  return {
    version: 2,
    transactions,
    categories: oldData.categories,
    budgets: oldData.budgets,
    settings: {
      ...DEFAULT_DATA_V2.settings,
      theme: oldData.settings.theme,
      currency: oldData.settings.currency,

      mainCurrency: oldData.settings.currency,
    },

    recurringTransactions: [],
    savingsGoals: [],
    debts: [],
    tags: []
  };
}

## Consideraciones técnicas para el programador

1. **Rendimiento:** Con muchas transacciones (1000+), los cálculos de saldos y filtros pueden ser lentos. Usar `useMemo` agresivamente para cachear cálculos derivados. Considerar virtualizar listas largas.

2. **Tamaño del archivo:** El index.html ya es grande (~1175 líneas). Con todas las mejoras podría llegar a 4000-5000 líneas. Considerar si vale la pena separar en módulos ES (con import maps) o mantener el single-file. Recomendación: mantener single-file por simplicidad de deploy, pero organizar el código con comentarios claros de sección.

3. **Compatibilidad:** Probar en Chrome Android (principal), Safari iOS, Chrome desktop. Babel transpila el JSX; las APIs modernas (Intl, Notification) tienen buen soporte.

4. **localStorage limits:** El límite típico es 5-10MB. Un JSON con 5000 transacciones pesa ~1MB. No debería ser problema, pero implementar compresión si crece mucho.

5. **Integridad de datos:** Toda operación que modifique `data` debe pasar por `setData()` para que el `useEffect` persista. Nunca mutar directamente.

6. **Estilo visual:** Mantener la estética actual (Fraunces + Inter, paleta cálida dorada, cards con bordes sutiles, animaciones suaves). Todas las nuevas pantallas deben seguir el mismo sistema de temas usando el objeto `t`.

7. **Íconos adicionales necesarios:** Agregar a los imports de Lucide: `Repeat, Bell, BellOff, Upload, FileJson, FileSpreadsheet, Merge, Archive, DollarSign, Percent, AlertTriangle, Flame, QrCode, Users, ArrowRightLeft`

8. **No romper datos existentes:** La migración v1→v2 debe ser automática, transparente y sin pérdida de datos. El usuario no debe notar nada excepto las nuevas funcionalidades.
